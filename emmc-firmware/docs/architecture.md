# eMMC 固件架构说明

## 分层设计

1. **firmware 层**：实现协议流程和控制逻辑，面向上层或任务框架提供统一接口，例如初始化、命令发送、数据传输等。
2. **HAL 层**：对真实硬件访问进行抽象，屏蔽不同芯片在寄存器访问、时钟、电源、DMA 等方面的差异。当前默认链接到 `sim/` 中的软仿真实现。
3. **SIM 层**：提供可在主机环境运行的寄存器与外设模型，模拟 eMMC 控制器状态机、响应码与数据缓冲，以便在无硬件条件下验证固件。
4. **Platform 层**：用于挂接启动代码、时钟管理以及系统资源申请。可根据项目需要集成 RTOS、裸机启动或单元测试运行时。
5. **Tests**：通过主机端编译执行的测试或示例程序，验证核心流程的正确性并提供用法范例。

## 寄存器仿真说明

- 采用 C 语言结构体与位域模拟关键寄存器，默认映射到 host 进程内存。
- 通过 HAL 提供的 `hal_emmc_reg_read/hal_emmc_reg_write` API 访问，可替换为真实 MMIO。
- 支持基本的状态机模拟：`POWER`、`CLOCK`、`CMD`、`RESP`、`DATA` 等寄存器。
- 内置命令响应表和伪随机数据缓冲，满足初始化、读写块的功能性验证需求。

## 代码风格与规范

- 默认使用 `clang-format` 或 `astyle` 保持一致的 C 代码风格（可在后续加入具体配置）。
- 所有公共接口头文件需放置于 `firmware/include` 或 `hal/include`。
- 禁止在固件层直接访问寄存器，必须通过 HAL API，确保可移植性。

## 后续扩展

- **中断与 DMA**：补充中断控制寄存器仿真，支持高速数据传输。
- **多通道支持**：根据具体控制器增加多通道/多卡槽逻辑。
- **可靠性增强**：加入 ECC、擦写次数统计、坏块管理等高级特性。
- **自动化测试**：扩展 `tests/`，引入单元测试框架及覆盖率统计。
